# تستر ماژول CalLut

تست هاست جدول کالیبراسیون فلش. کد **محصول** (`../cal_lut.c`) با **همان
آدرس‌های واقعی صفحه** کامپایل می‌شود: هارنس با `mmap` حافظه‌ای در `0x0800F000`
می‌سازد، پس خواندن مستقیم فلش توسط ماژول روی صفحهٔ شبیه‌سازی‌شده می‌افتد و
`ErasePage` / `ProgramHalfWords` بدلی در همان حافظه می‌نویسند.

فایل `stm32f1xx.h` کنار تست، **بدل** هدر ST است: `cal_lut.c` آن هدر را فقط
برای `NVIC_SystemReset()` می‌خواهد و هدر واقعی اسمبلی ARM دارد. اگر تستی به
ریست برسد، این بدل تست را با خطا تمام می‌کند.

## اجرا
```bash
./Firmware/Modules/CalLut/Tester/run_host_test_cal_lut.sh
```

## پوشش (۱۱۴ بررسی)
۱. برد نو: رکوردی نیست و جدول کامپایل‌شده سر کار می‌ماند.
۲. بازهٔ تعداد نقاط در `LUT_BEGIN`.
۳. کامیت بدون شروع → `NO_STAGE`.
۴. جدول ناقص (تکهٔ نرسیده) → `MISSING` و فلش اصلاً پاک نمی‌شود.
۵. شاخص نقطهٔ بیرون از بازه و کانال ناموجود رد می‌شوند.
۶. محور زنجیره باید اکیداً صعودی باشد → `CHAIN`.
۷. محور توان می‌تواند صاف باشد ولی افت ممنوع → `POWER`.
۸. CRC اشتباه پنل → `CRC` و فلش دست‌نخورده.
۹. مسیر موفق: نوشتن، تأیید، بازخوانی از خود فلش، و تعلیق/آزادسازی شارژر دور نوشتن.
۱۰. کامیت دوم روی **صفحهٔ دیگر** می‌نشیند (تناوب دو صفحه).
۱۱. خراب‌شدن رکورد تازه‌تر → بوت به رکورد سالم قدیمی‌تر برمی‌گردد.
۱۲. خرابی هر دو صفحه → بازگشت به جدول کامپایل‌شده.
۱۳. سکتور مردهٔ فلش → `FLASH`، نه شکست بی‌صدا.
