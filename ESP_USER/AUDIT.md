# ممیزی پنل کاربر پس از افزودن حذف تکی فایل

## دامنه

- فقط `ESP_USER`: مسیرهای HTTP، احراز هویت و نشست، حافظه و فرمت، حذف فایل، نمایش و دانلود، ذخیرهٔ وای‌فای، پیش‌نمایش و تست‌ها.
- در این کار هیچ تغییری در `Firmware` یا `CubeIDE` انجام نشده است؛ مقایسه با `04d1b8e` بدون اختلاف است.
- این گزارش نتیجهٔ بازبینی کد و آزمون میزبان است؛ تأیید عملکرد سخت‌افزار یا ممیزی امنیتی مستقل نیست.

## یافته‌ها و اقدام‌ها

| مورد | نتیجه |
|---|---|
| نبود حذف مستقل فایل و پنهان‌بودن فایل‌های غیرلاگ از مدیر | فهرست مدیر شامل همهٔ فایل‌های ریشه و دکمهٔ حذف مستقل است؛ مشاهدهٔ عمومی فقط فایل‌های لاگ را نشان می‌دهد. |
| جا نشدن همهٔ فایل‌ها در پاسخ محدود حافظه | صفحه‌بندی ۳۲تایی با `count`، `more` و `next`؛ فایل‌های صفحه‌های بعد هم در دسترس‌اند. |
| نام فایل دارای نقل‌قول، متن HTML یا UTF-8 | نام در JSON و HTML درست escape می‌شود؛ نام اصلی در `data-file` نگه داشته می‌شود، نه داخل کد اجرایی onclick. |
| مسیر خراب، نام خالی، NUL و تلاش برای خروج از ریشه | پیش از حذف رد می‌شود؛ حذف فقط POST و پس از احراز هویت مدیر است. پوشه و مسیر تو‌در‌تو پشتیبانی نمی‌شود؛ فایل‌های خود برنامه همگی در ریشه‌اند. |
| موفقیت جعلی هنگام خطای حذف | پاسخ موفق فقط پس از موفقیت `remove` و تأیید نبود فایل صادر می‌شود. خطای حافظه، فایل ناموجود و خطای حذف جدا هستند. |
| حذف روز جاری و باقی‌ماندن کش/سقف پر روز | کش روز و وضعیت آماده‌بودن فایل باطل می‌شوند؛ ثبت بعدی می‌تواند فایل تازهٔ سالم بسازد. RAM گزارش و سایر فایل‌ها پاک نمی‌شوند. |
| خروج مدیر یا اثر جانبی روی STM32 | حذف فایل نه نشست را باطل می‌کند، نه ریست می‌کند و نه فرمان UART می‌فرستد؛ آزمون مستقیم دارد. |
| پاسخ دیررس فهرست مدیر پس از خروج | با تغییر شناسهٔ نشست پاسخ دور انداخته می‌شود؛ فهرست خصوصی هنگام خروج پاک و مخفی می‌شود. |
| خرابی JSON و بازیابی وای‌فای با نام دارای `"` | بازتولید شد: JSON نامعتبر و نام بازیابی‌شده نادرست بود. کدگذاری/خواندن رشتهٔ JSON در `simple_json.h` اضافه شد و برای ذخیره و پاسخ وای‌فای استفاده می‌شود؛ رمز در پاسخ وجود ندارد. |

قرارداد متنی HTTP هم با مسیرهای ثبت‌شدهٔ واقعی هماهنگ شد: مسیرهای قدیمی کاربران/تم حذف شدند؛ خواندن عمومی وای‌فای فقط نام/وجود رمز را می‌دهد و مسیرهای تغییر همچنان مدیر می‌خواهند.

## شواهد آزمون

- `Tester/run_simple_tests.sh` با ASan/UBSan: **۳۴۰ بررسی C++، صفر شکست**.
- `host_test_panel_actions.js`: **۵۴ بررسی DOM**؛ حذف، تأیید/انصراف، فایل‌های تنظیمات، نام مخرب، قطع ارتباط، فهرست دیررس، فرمت و نشست بدون کوکی.
- `host_test_login_format.js`: **۱۷ بررسی کلیک واقعی پیش‌نمایش آفلاین**، شامل حذف فایل تنظیمات.
- تست‌های DOM اضافه‌ولتاژ، ساعت و CSV: موفق.
- درخواست HTTP به خود کد C++ برنامه با فایل‌سیستم دیسکی: نام فارسی/نقل‌قول‌دار، حذف فقط فایل منتخب، صفحه‌بندی، منع حذف عمومی و GET، رد مسیر فرار، حفظ نشست پس از حذف حساب و رگرسیون فرمت موفق.
- زنجیرهٔ DOM → HTTP → کد واقعی C++ → دیسک: حذف فایل منتخب، حفظ فایل دیگر، پیام موفقیت و خروج واقعی موفق.
- `tools/check_firmware_syntax.sh`: موفق؛ پارسر لینک **۱۲۴ بررسی، صفر شکست**. این ابزار بررسی میزبان است، نه ساخت باینری ESP با ابزار Arduino.
- `tools/audit_consistency.py`: **۵۶۷ قاعدهٔ سازگاری، صفر یافته**؛ این نتیجه به معنی نبود همهٔ خطاهای ممکن نیست.
- `tools/check_project_contract.py`، `tools/check_ai_rules.sh` و `git diff --check`: موفق.
- اندازهٔ رشتهٔ واقعی پنل: **۱۷۴۶۷۸ از ۱۷۵۰۰۰ بایت**؛ فضای باقی‌مانده محدود است.

## رفتار عمدی و محدودیت‌ها

- حذف `/users.json` اکنون مجاز است، اما پس از ریست، نبود فایل حساب باعث ساخت حساب اولیه می‌شود؛ تأیید رابط این پیامد را صریح می‌گوید.
- حذف تنظیمات، دادهٔ فعال RAM را بازنشانی نمی‌کند. ذخیرهٔ بعدی می‌تواند فایل را دوباره بسازد؛ حذف روز جاری هم ثبت آینده را متوقف نمی‌کند.
- حذف فایل یک عمل بازگشت‌ناپذیر است. فایل‌های مهم باید پیش از حذف پشتیبان داشته باشند؛ این تغییر امکان دانلود رمزها یا فایل حساب را اضافه نمی‌کند.
- ذخیره‌سازی برنامه تخت و در ریشه است؛ حذف پوشه، مسیر تو‌در‌تو و نام دارای کاراکتر کنترلی پذیرفته نمی‌شود.
- پیش‌نمایش، میزبان و HTTP جایگزین آزمون LittleFS روی ESP واقعی نیستند. mount، اندازه/چیدمان فلش، قطع تغذیه وسط حذف و فرسودگی فلش نیازمند آزمون روی بردند.
- بررسی نشده: باینری واقعی ESP8266/ESP32، اندازهٔ heap روی برد، UART فیزیکی و رفتار توان/باتری روی سخت‌افزار.
