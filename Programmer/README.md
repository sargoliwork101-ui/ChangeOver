# Programmer — فلش‌کردن برد بدون از دست دادن کالیبراسیون

این پوشه ابزار **روی لپ‌تاپ** است، نه کد برد. تنها کاری که کد برد نمی‌تواند بکند
همین‌جاست: نوشتن برنامه روی تراشه.

**توضیح کامل هر اسکریپت و روش اجرا: [`SCRIPTS.md`](SCRIPTS.md)** — این فایل
فقط نمای کلی و هشدارهای مشترک است.

## چرا این اسکریپت لازم است

STM32F103 وقتی قفل خواندن (RDP سطح ۱) دارد، با SWD فقط بعد از پاک‌کردن کامل تراشه
برنامه می‌پذیرد. آن پاک‌کردن این دو ناحیه را هم می‌برد:

| ناحیه | آدرس | اندازه |
|---|---|---|
| برنامه | `0x08000000` | ۵۶ کیلوبایت |
| بانک پارامترها | `0x0800E000` | ۴ کیلوبایت |
| جدول کالیبراسیون | `0x0800F000` | ۲ کیلوبایت |
| یدک | `0x0800F800` | ۲ کیلوبایت |

اسکریپت ۸ کیلوبایت ناحیهٔ داده (`0x0800E000..0x0800FFFF`) را قبل از پاک‌کردن
می‌خواند و بعد از نوشتن برنامه برمی‌گرداند و بررسی می‌کند.

## پیش‌نیاز

1. STM32CubeProgrammer نصب باشد.
2. `STM32_Programmer_CLI` روی `PATH` باشد، یا `--cli` مسیر کاملش را بدهد، یا
   متغیر محیطی `STM32_PROGRAMMER_CLI` ست شود.
3. ST-Link روی کانکتور CON4 (SWDIO / SWCLK / NRST / 3.3V / GND).

## کدام اسکریپت، کِی

| موقعیت | اسکریپت |
|---|---|
| برد نو، اولین بار | `first_flash_changeover.py` |
| هر بار بعد، با حفظ پارامتر و کالیبراسیون | `flash_changeover.py` |
| فقط برگرداندن پشتیبان | `flash_changeover.py --restore-only` |

```bash
# اولین بار روی برد نو (اول با --dry-run)
python3 Programmer/first_flash_changeover.py \
    --image build/ChangeOver.hex --label board7

# همهٔ بارهای بعد
python3 Programmer/flash_changeover.py --image build/ChangeOver.hex \
    --backup Programmer/backups/params_v1.90_board7.bin
```

## قواعدی که اسکریپت خودش رعایت می‌کند

- بدون پشتیبان سالم هیچ چیزی پاک نمی‌شود.
- پشتیبانی که اندازه‌اش ۸ کیلوبایت نباشد رد می‌شود.
- پشتیبانی که تمامش `0xFF` باشد رد می‌شود (یعنی برد خوانده نشده یا برد اشتباه است).
- فایل پشتیبان بعد از برگشت با `-v` روی خود فلش بررسی می‌شود.
- هر گام خروجی ابزار را چاپ می‌کند؛ خطا اجرا را متوقف می‌کند، نه اینکه رد شود.

## دو نکته که باید بدانید

1. **قفل با این اسکریپت یا با کد برد؟** هر دو راه وجود دارد و با هم تعارض ندارند.
   راه اصلی، `MODULE_FLASH_LOCK = 1` در `Firmware/Config/Inc/modules_enable.h` است؛
   برد در اولین بوت خودش قفل می‌شود. `--lock` این اسکریپت برای وقتی است که بخواهید
   همان لحظه و از روی لپ‌تاپ قفل کنید. هر کدام اول انجام شود، دیگری «قفل است» را
   می‌بیند و کاری نمی‌کند.
2. **پشتیبان کهنه خطرناک است.** اگر ساختار پارامترها یا جدول کالیبراسیون بین دو بیلد
   عوض شده باشد، برگرداندن پشتیبان قدیمی برنامه را با عدد بی‌معنی بالا می‌آورد و
   هیچ خطایی هم نمی‌دهد. نام فایل پشتیبان را با نسخهٔ بیلد بگذارید (مثل نمونه‌ها) و
   بعد از هر فلش، مقادیر کالیبراسیون را در پنل یک بار ببینید.

## آزمایش‌شده تا کجا

- هر دو اسکریپت با ابزار بدلی روی چهار حالت آزمایش شدند (برد نو، برد دارای داده،
  برد قفل‌شده، فایل ناموجود) و جدول کامل در `SCRIPTS.md` است.

- منطق اسکریپت روی کامپیوتر آزمایش شده است: ترتیب گام‌ها، رد پشتیبان کهنه، و
  `--dry-run`.
- دستورهای `STM32_Programmer_CLI` روی برد واقعی آزمایش نشده‌اند؛ اولین بار با
  `--dry-run` و بعد روی یک برد آزمایشی اجرا شود. به‌خصوص مقدار `RDP=0xA5` را یک بار
  با `-ob displ` ببینید و مطمئن شوید سطح ۱ گزارش می‌شود.
- اگر برگرداندن داده با خطای `RDP` متوقف شد، یعنی قفل پیش از نوشتن برگردانده شده؛
  ترتیب این اسکریپت همان است که در بالا آمده و نباید جابه‌جا شود.
