# استاندارد کامنت‌گذاری کد

## هدف

کامنت‌ها باید برای انتقال Intent، قرارداد API، پیش‌شرط‌ها، اثرات جانبی، محدودیت‌های زمانی و تصمیم‌های ایمنی نوشته شوند. کامنت‌ها به‌تنهایی باعث MISRA Compliance نمی‌شوند؛ نتیجه‌ی نهایی با Static Analysis و Review مشخص می‌شود.

## هدر فایل

تمام فایل‌های `.c` و `.h` باید توضیح دهند:

- نام فایل
- مسئولیت ماژول
- لایه‌ی معماری
- مرزهای HAL/FreeRTOS
- ملاحظات ایمنی
- وضعیت تحلیل MISRA

## کامنت تابع

برای هر تابع public و private موارد زیر ثبت شود:

- `@brief`: وظیفه‌ی دقیق تابع
- `@param`: نقش هر پارامتر
- `@return`: معنی خروجی در توابع غیر `void`
- `@pre`: پیش‌شرط‌ها در صورت وجود
- `@post`: تغییر تضمین‌شده در صورت وجود
- `@safety`: محدودیت‌های ایمنی
- `@misra`: نکته‌ی تحلیل یا Deviation مرتبط

## ISR و Callback

برای تابعی که از ISR یا Callback صدا زده می‌شود باید صریحاً نوشته شود:

- تابع Blocking نیست.
- فقط APIهای `FromISR` استفاده می‌شوند.
- تخصیص حافظه انجام نمی‌شود.
- پردازش اصلی به Task منتقل می‌شود.

## همگام‌سازی کامنت و کد

کامنت نباید رفتار متفاوتی از کد توصیف کند. در صورت تغییر منطق، کامنت همان Commit باید به‌روزرسانی شود.

## ممنوع

- کامنت‌های بی‌معنی مثل `set variable` برای هر خط
- توضیح دادن syntax به‌جای Intent
- ادعای «کاملاً MISRA» بدون گزارش ابزار
- نگه‌داشتن کامنتی که با کد فعلی تناقض دارد
- مخفی‌کردن Deviation در کامنت به‌جای ثبت در `docs/deviation-record.md`
