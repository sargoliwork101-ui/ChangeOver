# تستر ماژول Changeover

تست هاست ماشین حالت تغییر مسیر (ورودی ↔ باتری). کد **محصول**
(`../changeover.c`) بدون هیچ تغییری کامپایل می‌شود و با یک «دنیای بدلی»
رانده می‌شود:

| بدل | کار |
|---|---|
| ساعت کرنل | `osKernelGetTickCount()` یک شمارندهٔ ساده است که خود تست جلو می‌برد، پس ۳ ثانیه در چند میکروثانیه می‌گذرد |
| `func__BspGpio_Write` | فقط ثبت می‌کند: آخرین مقدار خط محافظ باتری و تعداد دفعات نوشتن (تا ثابت شود پایهٔ رانده‌شده دوباره رانده نمی‌شود) |
| وتوی عدم‌توازن و وتوی باتری خراب | پرچم‌هایی که تست روشن/خاموش می‌کند |

## اجرا

```bash
./Firmware/Modules/Changeover/Tester/run_host_test_changeover.sh
```

همین اجراکننده داخل `tools/check_firmware_syntax.sh` هم صدا زده می‌شود، پس
یک تست قرمز دروازه را می‌شکند.

## چه چیزهایی پوشش دارد (۱۱۴ بررسی)

۱. شروع از `BOOT`؛ snapshot خالی یا نامعتبر هیچ تصمیمی نمی‌سازد و پایه را
   تکان نمی‌دهد.
۲. نگاشت ساده: ورودی حاضر → `INPUT`، نبود ورودی → `BATTERY`.
۳. هر فالتی → `FAULT` و بدون دست‌زدن به پایه.
۴. قطع بحرانی زیر ۲۰۸۰۰mV با فیلتر دقیقاً ۳ ثانیه (یک میلی‌ثانیه زودتر: نه).
۵. **رگرسیون v1.81:** باتری زیر ۲۱۰۰۰ می‌رود و وسط پنجره به ۲۱۱۰۰ (داخل نوار
   هیسترزیس) برمی‌گردد — شمارش نباید بخوابد؛ و بهبود واقعی تا ۲۱۲۰۰ باید
   شمارش را رها کند.
۶. وصل مجدد فقط با حضور ورودی + ۲۱۲۰۰mV + ۳ ثانیه (تصمیم کاربر ج-۲)، و
   رهاشدن فیلتر با قطع ورودی در میانهٔ راه.
۷. وتوی سناریو ۵ (عدم‌توازن قفل‌شده) → فوری `SAFE`، و فالت سخت بالاتر از آن.
۸. وتوی سناریو ۶ (باتری خراب) → فوری `SAFE`.
۹. سرریز شمارندهٔ تیک (۴۹٫۷ روز) وسط فیلتر ۳ ثانیه.
