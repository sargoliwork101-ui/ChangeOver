# ماژول Changeover

## وضعیت

پیاده‌سازی کامل منطق قطع/وصل با فیلتر 3000ms، `MODULE_CHANGEOVER = 1` است تا منطق واقعی روی تسک کنترل اجرا و روی برد تست شود. فقط از داده‌های مجاز استفاده می‌کند: `snapshot.valid`, `snapshot.v_bat24_mv`, `snapshot.input_present`, `fault_mask` (قفل باتری کم، پنجرهٔ ولتاژ سالم و محافظ چرخه داخلی‌اند). تبدیل زمان فقط با `rtos_time.h` و بدون فرض `tick=1ms`. فقط `BSP_GPIO_PROTECT_BATTERY` (PB11 منطقی) استفاده می‌شود؛ `PB5` و `PB7` ممنوع و به هیچ‌وجه تغییر نمی‌کنند. `board_pins.h`، HAL و پایه فیزیکی در ماژول ممنوع است.

منطق (snapshot-first):
- اگر `snapshot==NULL` یا `snapshot.valid==false` → هیچ تصمیمی، `state` حفظ، `PB11` حفظ، تایمرهای pending reset، `fault` هم در این حالت `state` را تغییر نمی‌دهد، زمان نامعتبر جزو 3000ms حساب نمی‌شود.
- فقط وقتی `snapshot` معتبر است و `fault_mask != FAULT_NONE` → `state=APP_STATE_FAULT` بدون تغییر هیچ pin.
- قطع با گیت: `v_bat24_mv<21000` و قفل داخلی باتری کم (ست زیر ۲۱۰۰۰، پاک در ۲۱۲۰۰) به‌مدت پیوسته 3000ms → قطع باتری (PB11 منطقی true = High فیزیکی = قطع).
- قطع مستقل: `v_bat24_mv<20800` مستقل از فلگ، به‌مدت پیوسته 3000ms → قطع باتری.
- بوت: PB11 در حالت قطع امن می‌ماند. بعد از snapshot معتبر، نبود خطای مسدودکننده/وتو و ولتاژ `v_bat24_mv≥21200`، مسیر وصل می‌شود؛ شرط ۳۰ ثانیهٔ ورودی برای شروع بوت لازم نیست.
- وصل مجدد پس از قطع کم‌باتری حین کار: `input_present==true` پایدار 30000ms + `v_bat24_mv≥21200` به‌مدت پیوسته 3000ms → وصل باتری. هیسترزیس ۲۱۰۰۰/۲۱۲۰۰mV حفظ می‌شود؛ تاخیر ورودی فقط برای جلوگیری از چرخهٔ قطع/وصل بعد از افت ولتاژ است.
- بازیابی بدون برق شهر (دستور کاربر ۲۰۲۶-۱۰-۲۳): اگر باتری بعد از قطع (یا با تعویض) به ولتاژ سالم برگردد، پارک نشده باشد، اوج استراحت آن به آستانهٔ ۱۶۵ (پیش‌فرض ۲۵۰۰۰mV) رسیده باشد و **بدون هیچ وقفه‌ای** مدت ۱۵۰ (پیش‌فرض ۱۰ ثانیه) در آستانهٔ ۲۱۲۰۰mV یا بالاتر بماند، وصل مجدد بدون برق شهر مجاز است و بعد فیلتر ۳ ثانیه‌ای هم اجرا می‌شود (در عمل حدود ۱۳ ثانیه). یک افتِ کوتاه وسط این ۱۰ ثانیه، شمارش را از صفر شروع می‌کند. اگر نوسان برق شهر یا نبود ورودی، هنوز ۳۰ ثانیهٔ پایداری ورودی هم لازم است.
- محافظ چرخه (همان دستور ۲۰۲۶-۱۰-۲۳): اگر بعد از یک وصلِ بدون برق شهر، باتری ظرف `CHANGEOVER_CYCLE_GUARD_MS` (۶۰ ثانیه) دوباره قطع شود، یعنی واقعاً ضعیف است؛ از آن به بعد وصل خودکار بدون برق شهر قفل می‌شود و فقط برگشت برق شهر (۳۰ ثانیه پایدار + ۳ ثانیه) آن را باز می‌کند.
- سیگنال «نبود باتری» ماژول Fault برای این تصمیم استفاده **نمی‌شود**: سه ورودی حس، مقسم مستقل از سه پین کانکتور باتری‌اند و قطع یک سیم به‌طور مطمئن هیچ‌کدام را زیر آستانهٔ نبود نمی‌برد (دستور ۲۰۲۶-۱۰-۲۳).

## سناریوی ۸ — باتری ضعیف (دستور کاربر ۲۰۲۶-۱۰-۲۳)

سناریوی ۸ یک چهرهٔ مستقل مثل سناریوهای ۵/۶/۷ دارد و همهٔ اعدادش از پنل تنظیم می‌شود؛ هیچ عددی از سناریوی دیگری قرض گرفته نمی‌شود. حکم در همین ماژول قفل می‌شود، چون فقط همین‌جا وصلِ بدون برق شهر و قطعِ بعد از آن دیده می‌شود؛ UI فقط آن را رسم می‌کند.

رفتار حکم:

- **وصلِ بدون برق شهر (v1.90، دستور نهایی کاربر):** بعد از قطعِ ولتاژ پایین، پک فقط وقتی روی بار برمی‌گردد که استراحتِ آن به ۱۶۵ (پیش‌فرض ۲۵٬۰۰۰ میلی‌ولت) رسیده باشد و پنجرهٔ سالم (۱۵۰) کامل شده باشد. پکی که فقط تا ۲۳ ولت برمی‌گردد **دشارژ شده** است و تا رسیدن شارژ وصل نمی‌شود.
- **استراحت یعنی بدون بار و بدون شارژ (بازبینی ۲۰۲۶-۱۰-۲۳):** عدد استراحت فقط از نمونه‌های **بدون برق شهر** گرفته می‌شود. تا وقتی برق شهر هست، شارژر همان پک را شارژ می‌کند و ولتاژ پایانه‌اش ولتاژ شارژ است (تا حدود ۲۷ ولت)، نه استراحت؛ شمردن آن باعث می‌شد یک چشمک کوتاه برق شهر «استراحت بالای ۲۵ ولت» جعل کند و پکِ خالی در قطع بعدی روی بار برگردد و حکم کاذب «فرسوده» بگیرد.
- **قفل حکم (v1.88/v1.90):** همان یک وصل که با استراحت ۲۵ ولت یا بالاتر انجام شد، اگر داخل پنجرهٔ محافظ (۱۴۹) به قطع برسد و شناسهٔ ۱۴۷ صفر نباشد، حکم «باتری فرسوده» را قفل می‌کند. دلیل: باتریِ نو که فقط خالی شده هرگز تا ۲۵ ولت بالا نمی‌آید؛ پکی که با استراحت ۲۵ ولت یا بالاتر باز هم زیر بار فرو می‌ریزد فرسوده است.
- **سقف تلاش (v1.90، تصمیم نهایی کاربر ۲۰۲۶-۱۰-۲۳):** فقط **یک** وصلِ بدون برق شهر، آن هم فقط برای پکی که به آستانهٔ استراحت رسیده است. اگر بعد از آن وصل داخل پنجرهٔ محافظ (۱۴۹) دوباره قطع شود، مسیر باتری **پارک** می‌شود و تا برگشت برق شهر وصلِ خودکار بدون برق شهر انجام نمی‌شود. برگشت برق شهر، کلید ریست پنل و `func__Changeover_WeakVerdictReset()` این اجازه را برمی‌گردانند. (این خط، سوییچ مسیر باتری است، نه رلهٔ شارژر؛ رلهٔ شارژر کاری به این سناریو ندارد.)
- **نگه‌داشتن خروجی:** تا وقتی حکم برجاست و ۱۵۷ یک است و برق شهر نیست، `BSP_GPIO_PROTECT_BATTERY` فعال می‌ماند و حالت `APP_STATE_SAFE` است؛ تایمرها صفر می‌شوند. شارژ بدون برق شهر انجام نمی‌شود، پس شارژر دست نمی‌خورد.
- **پاک‌شدن:** فقط با ۱۴۷ = ۰، با ولتاژ سالمِ پیوسته (≥ ۲۱۲۰۰mV) به مدت ۱۴۸، یا با دکمهٔ «پاک‌کردن حکم» کارت ۸؛ بعد از پاک‌شدن فقط **یک** تلاش مجدد مجاز است.
- **ریست دستی (شناسهٔ ۲۰۴):** `func__Changeover_WeakVerdictReset()` همان کاری را می‌کند که پایان استراحت می‌کند: حکم و تایمرش صفر، شمارندهٔ استراحت پاک، و امکان همان یک تلاش مجدد برمی‌گردد؛ خروجی که با حکم بسته شده بود همان لحظه آزاد می‌شود (برق شهر لازم نیست). این شناسه دستور است، نه پارامتر: نه ذخیره می‌شود نه در پنل عدد دارد؛ پنل فقط دکمه را می‌فرستد و جواب «حکمی بود یا نه» را از پژواک همان فریم می‌خواند. خود ریست پایهٔ PB11 را دست نمی‌زند؛ تصمیم وصل/قطع بعدی را همان گیت‌های عادی می‌گیرند (اگر ولتاژ واقعاً پایین است، مسیر بسته می‌ماند).
- **استثنای روشن‌شدن اول (تصمیم نهایی کاربر ۲۰۲۶-۱۰-۲۳: بماند):** اگر دستگاه بدون برق شهر روشن شود و هنوز هیچ قطعی نداشته باشد، همان لحظه مسیر باتری را وصل می‌کند؛ حتی اگر استراحت زیر ۱۶۵ باشد. دلیل: آن لحظه هنوز ولتاژ بی‌بار و استراحتی اندازه‌گیری نشده و آستانهٔ استراحت دربارهٔ «برگشتن بعد از قطع» است، نه راه‌اندازی اول. عمداً بسته نمی‌شود تا باتری سالمِ نیمه‌پر (بی‌بار حدود ۲۴ ولت) بدون برق شهر دستگاه را روشن کند.
- **شرط «باتری ≥ ۲۱۲۰۰ میلی‌ولت» با برق ورودی (تصمیم نهایی کاربر ۲۰۲۶-۱۰-۲۳: بماند):** با بودن برق ورودی هم وصل خروجی هم ۳۰ ثانیه ورودیِ ثابت و هم ۲۱۲۰۰ میلی‌ولت باتری را می‌خواهد، هرچند بار از ورودی تغذیه می‌شود. دلیل: اگر برق ورودی همان لحظه قطع شود، بار نباید روی باتری خالی بیفتد.
- **برگشت برق شهر حکم را پاک نمی‌کند**؛ فقط مسیر باتری از راه ورودی برمی‌گردد و حکم سر جایش می‌ماند.
- **چهره:** قرمز چشمک‌زن با دوره/سهم خودش (سبز و زرد خاموش) و بوق با الگوی خودش؛ این چهره در `func__Ui_ScenarioWeakBattery_Tick` رسم می‌شود. از v1.88 فقط وقتی برق شهر نیست نمایش داده می‌شود؛ با برگشت برق شهر چهرهٔ شارژ عادی برمی‌گردد و حکم سر جایش می‌ماند.
- **قطع سیم باتری بدون برق ورودی (تصمیم کاربر ۲۰۲۶-۱۰-۲۳: سکوت):** اگر سیم باتری حین کار قطع شود و برق ورودی هم نباشد، ولتاژ خوانده‌شده حدود صفر می‌شود. برد آن را «پک خالی» می‌داند: بعد از فیلتر ۳ ثانیه مسیر باتری بسته می‌شود، همهٔ چراغ‌ها و بوق خاموش می‌مانند و هیچ حکمی زده نمی‌شود؛ آلارم «قطع باتری» عمداً فقط با برق ورودی حاضر کار می‌کند. وضعیت تا برگشت برق ورودی همین می‌ماند.
- **چراغ‌ها هنگام قطع (v1.89):** تا وقتی مسیر باتری بسته است و برق ورودی نیست، UI هر سه LED و بوق را خاموش نگه می‌دارد (`func__Changeover_PathBlocked`)؛ با برگشت برق ورودی چهرهٔ شارژ خودش برمی‌گردد.
- **نمایش در پنل‌ها:** `func__Changeover_WeakVerdictActive` حکم را در بیت `0x10` بایت وضعیت فریم زنده (`fl2`) می‌گذارد؛ پنل کالیبراسیون چراغ همیشه‌سوار «باتری ضعیف» و خط وضعیت کارت ۸ را از همین بیت می‌کشد و پنل کاربری ESP همان جملهٔ وضعیت را نشان می‌دهد.

## توابع

| نام | کار |
|---|---|
| `func__Changeover_Init` | `s_state=APP_STATE_BOOT`، تایمرها inactive، `protect=true` و PB11 روی قطع امن؛ اتصال تا snapshot معتبر و ولتاژ ≥۲۱۲۰۰mV معطل می‌ماند |
| `func__Changeover_Evaluate(snap, faults)` | اگر `snap==NULL`/`!valid` → حفظ state/PB11 و reset تایمر (fault هم FAULT نمی‌شود)؛ وگرنه اگر `fault!=0` → `FAULT` بدون pin؛ وگرنه پنجرهٔ ولتاژ سالمِ پیوسته (۱۰s) و محافظ چرخه (۶۰s)، ارزیابی قطع (`v<20800` مستقل و `v<21000&&flag` گیت) و وصل (`input` پایدار ۳۰s یا پنجرهٔ سالمِ کامل، با `v>=21200`) هر کدام پیوسته 3000ms فقط روی `BSP_GPIO_PROTECT_BATTERY`؛ زمان با `func__Rtos_MillisecondsToTicks` و بدون فرض `tick=1ms` |
| `TaskControl` | فقط اگر Changeover یا Charger یا Jitter یک باشد ساخته می‌شود |

حالت‌ها: `BOOT`، `INPUT`، `BATTERY`، `FAULT`، `SAFE` — `IDLE` برای حالت معتبر استفاده نمی‌شود؛ پس از `BOOT` و با `snapshot` معتبر بدون cut → `BATTERY` (input false) یا `INPUT` (input true)، پس از cut → `SAFE`، پس از reconnect → `INPUT` (یا `BATTERY` اگر وصل از راه بازیابی بدون ورودی باشد)؛ `MODULE_CHANGEOVER` در build تست برد 1 است.

## پایه‌ها

Changeover **فقط** از سیگنال منطقی `BSP_GPIO_PROTECT_BATTERY` (PB11 فیزیکی) استفاده می‌کند. پایهٔ فیزیکی و قطبیت در BSP پنهان است؛ ماژول `board_pins.h` و HAL را include نمی‌کند.

جدول زیر فقط مرجع فیزیکی برد فعلی است:

| پایه منطقی | پایه فیزیکی | لیبل | نقش | HIGH یعنی (شماتیک) |
|---|---|---|---|---|
| `BSP_GPIO_PROTECT_BATTERY` | PB11 | `MCU_LOW_BAT` / `MCU_PROTECT_BATT` | قطع مسیر باتری Q17 | High = Q17 روشن و مسیر قطع (امن)؛ Low = مسیر باتری وصل (فعال-بالا) |
| `BSP_GPIO_BATTERY_SWITCH` (PB5) | PB5 | `MCU_BAT_SWITCH` | — | **ممنوع: تغییر نمی‌کند** |
| `BSP_GPIO_RELAY` (PB7) | PB7 | `MCU_PROTECT_CHARGER` | — | **ممنوع: تغییر نمی‌کند** |

قطبیت از شماتیک است، روی برد اندازه نشده. مسیر شماتیک: PB11 → R45 → بیس Q17؛ High یعنی Q17 روشن، `GATE_ON_OFF` به زمین کشیده می‌شود، Q12 خاموش می‌ماند و گیت Q15/Q16 بالا می‌ماند؛ پس زوج سری بسته است و باتری به OUT نمی‌رسد. با Low، Q17 خاموش و `GATE_ON_OFF` آزاد می‌شود؛ فقط اگر ورودی هم قطع باشد (Q11 خاموش) خط بالا می‌آید و باتری روی خروجی می‌نشیند.

## پیش‌فرض امن

- بوت: `func__BspGpio_Init` پایه را فیزیکی High می‌گذارد که قطع امن است. `func__Changeover_Init` نیز حفاظت را فعال نگه می‌دارد. فقط پس از snapshot معتبر، نبود خطای مسدودکننده و رسیدن ولتاژ پک به ۲۱۲۰۰mV، مسیر وصل می‌شود؛ سپس state از ورودی حاضر/غایب تعیین می‌شود.
- اگر `snapshot==NULL` یا `!valid` → `state` و `PB11` حفظ، تایمرهای pending reset، حتی `fault!=0` هم `FAULT` نمی‌شود و زمان نامعتبر جزو 3000ms حساب نمی‌شود.
- فقط وقتی `snapshot` معتبر است و `fault!=0` → `state=FAULT` بدون تغییر هیچ pin (تایمرها reset).
- زمان‌گیری فقط با `osKernelGetTickCount()` و `func__Rtos_MillisecondsToTicks(CHANGEOVER_DURATION_MS)` و بدون فرض `tick=1ms`؛ `MillisecondsToTicks` نرخ تیک را از `osKernelGetTickFreq()` می‌گیرد.
- تا اندازه‌گیری قطبیت، `PB11` در CubeMX نیز High (Safe) نگه داشته شود.

## درخت اتصال

صدا زده می‌شود از (وقتی فلگ ۱ شود):

```text
rtos_app.c → TaskControl → task_control.c
  measurement_snapshot_t snap; fault_mask_t faults;
  (void)func__Measurement_GetSnapshot(&snap); // valid, v_bat24_mv, input_present
  faults = func__Fault_Get();
  state = func__Changeover_Evaluate(&snap, faults);
    ├── snap==NULL || !valid → preserve state/PB11, reset timers, fault هم FAULT نمی‌شود (invalid not counted)
    ├── else if fault!=0 → state=FAULT, no pin change
    ├── else if v<20800 for 3000ms → BSP_GPIO_PROTECT_BATTERY = true (High physical, cut) → SAFE
    ├── else if v<21000 && قفل داخلی باتری کم (21000/21200) for 3000ms → cut → SAFE
    ├── else if (input پایدار ۳۰s، یا ۱۰s ولتاژ سالمِ پیوسته بدون ورودی و بدون محافظ چرخه) && v>=21200 for 3000ms → BSP_GPIO_PROTECT_BATTERY = false (Low physical, connect) → INPUT/BATTERY
    └── else valid without cut → INPUT (input true) یا BATTERY (input false)
```
